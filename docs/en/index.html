The problem

Standing up six containers is easy. It is what comes after that takes three hours.

Opening every UI, copying an API key, pasting it into another one, starting over, getting a port wrong, and finding out three days later that imports are copying 40 GB instead of making a link. PlugArr automates that part.

indexers pushed, fullSync download client and import notification

Every link is read back from the target API after creation. The final report does not say “I sent a POST”, it says “the link exists”.

The trap everyone falls into

A single /data mount, or every import copies the file

Mounting /downloads and /media separately gives you two filesystems as seen from inside the container. Hardlinks become impossible. PlugArr enforces a single mount in every container.

${DATA_ROOT}/                    ->  /data   (in EVERY container)
├── torrents/
│   ├── movies/
│   ├── tv/
│   ├── music/
│   └── .incomplete/
└── media/
    ├── movies/                  <- Radarr root folder + Jellyfin library
    ├── tv/                      <- Sonarr root folder + Jellyfin library
    └── music/                   <- Lidarr root folder + Jellyfin library

The preflight does not merely hope for it: it creates a real hardlink between torrents/ and media/, and tells you whether it worked.

Installation

Windows: a single file, no Python

Download plugarr.exe, open a terminal in your downloads folder, and run it. Docker Desktop is the only requirement: the executable ships its own interpreter. 20 MB, roughly a second and a half to start.

windows
> .\plugarr.exe

Windows SmartScreen may warn you on first launch: the binary is not signed, a code signing certificate costing several hundred euros a year. “More info”, then “Run anyway”.

Other platforms

Docker Engine with the docker compose plugin, and Python 3.12 or newer. Four profiles: windows, generic-linux, unraid, synology. The one matching your machine is preselected.

bash
$ pipx install git+https://github.com/yannickuhrig1/plugarr

$ plugarr              # interactive wizard
$ plugarr scan         # detect an existing stack
$ plugarr adopt        # wire it without recreating anything
$ plugarr serve        # admin page
$ plugarr doctor       # diagnose an installation
$ plugarr uninstall    # never touches your media

The package is not published on PyPI yet.

Secrets per installation

20-character passwords and API keys drawn from Python's cryptographic source, roughly 125 bits of entropy. No default password exists.

A VPN that does not leak

The download client does not start until Gluetun is healthy. Verified with deliberately wrong credentials: qBittorrent never leaves the created state.

A log you can attach to an issue

plugarr.log contains every step and the full traceback of an error. Passwords and API keys are replaced by their name before writing.

Your quality profiles

PlugArr does not reimplement the TRaSH Guides: it installs Recyclarr, picks an official template, and starts the first sync.

Read before you start

What this project does not do

PlugArr provides, hosts and recommends no indexer, no tracker, no content, and preconfigures none. No list ships with the code: the wizard's comes from your own Prowlarr. It is a personal media library automation tool. What you plug into it, and its legality, are your business.
